An agent runtime

Agents that keep working when nobody is watching.

thirdshift is the runtime around an agent: a tool server, a workflow engine that survives crashes, a team of agents, a gateway for model calls and a proxy between the agents. It is written against the protocols themselves, with no agent framework and no MCP SDK, and every layer was measured against the simplest thing it should beat.

Architecture

Five layers, each calling the one below

1,594 lines of Python, SQLite for every kind of state, and Pydantic at every boundary. The proxy and the gateway are opt-in, each behind one environment variable.

  1. Durable engineRuns a workflow one step at a time and writes the state and the next step in a single transaction. Retries with backoff, approval gates and bounded loops. durable.py
  2. Agent teamA researcher, a coder, a sandbox runner and three reviewers, with a supervisor that is four fixed rules. Every hand-off is a strict model. swarm.py
  3. Security proxyMasks personal data, cuts out text that addresses an agent as instructions, limits each role to its own tools and keeps a hash-chained audit log. proxy.py
  4. GatewayExact-match cache, a daily budget with a soft and a hard limit, routing between two models by prompt complexity, and fallback when one is down. gateway.py
  5. MCP serverRaw JSON-RPC over stdio in both protocol eras: the stateless 2026 revision and the older handshake. Tools are granted by scope, and code runs in a sandbox. server.py
  6. OutsideThe footnoted documentation index, reached only through the MCP server, and two local models served by Ollama.
How it works

This is the event log of a real run of the research workflow. It searched the docs through the MCP server, stopped for a person, and was approved from a different process, which picked the run up from its checkpoint.

Started, waiting for a worker to lease it.

A worker holds the lease. Each finished step is checkpointed.

A step failed. It runs again after 2 s, then 4 s.

Stopped at a gate until a person approves or rejects.
done
Every step finished.
failed
Out of attempts, or a step said retrying would not help.

If the worker dies, the run stays in running with a lease that expires after 300 seconds. Whoever claims it next resumes at the step that was in progress. Attempts are counted before a step runs, so a step that kills its worker runs out of attempts instead of looping forever.

  • Money. The team costs 25 times as much per passing task as the coder alone. Routing the more complex half of the tasks to the larger model cost 28% less than always using it, for the same number of passes. The gateway’s hard limit refuses calls once a daily budget is spent, and a run stopped that way fails at once without retrying.
  • Time. 3.4 seconds a task for the coder and 21.9 for the team. A failed step waits 2 seconds, then 4. A dead worker’s run is picked up when its 300-second lease expires.
  • Efficiency. Only exact-match caching is on by default, because no threshold serves paraphrases without also serving a wrong answer. The two models fail different tasks, so trying the small one first and escalating would pass 9 of 10, if there were a reliable way to check the result.
Impact

What this is evidence of, and what it is not

thirdshift has no users. Its impact is what the measurements show.

What held up

  • A crash costs one step. Tested by killing a real worker process, in CI on every push.
  • Prompt injection between agents is real and cheap, and removing the text stops the form it takes here. Fencing the content as data did not help on its own.
  • A tool an agent is not granted does not exist for it. Calling it returns the same error as a name that was never real.

What did not, and the limits

  • More agents made the result worse at this model size. A larger model is untested.
  • The evals are small and were written by the builder: ten coding tasks, sixteen cache pairs and fifteen votes per row. A difference of one is noise.
  • The proxy’s patterns are a list, and a reworded attack passes them.
  • The MCP server has not met a third-party client, and its sandbox is macOS only.
Reproduce

Every number has a command

uv run python tests/test_durable.py        # the killed-worker test, no model needed
uv run thirdshift eval-swarm evals/tasks.jsonl       # team against one coder
uv run thirdshift eval-injection                     # reviewers and the planted comment
uv run thirdshift eval-routing evals/tasks.jsonl     # routing policies
uv run thirdshift eval-cache evals/cache_pairs.jsonl # semantic cache, no model needed

thirdshift is half of a pair. footnoted is the documentation system it serves as tools, and the teardown gives the verdict on every technique in both.
